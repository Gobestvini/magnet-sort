# Magnet Sort — GDD v0.4

Дата: 2026-10-12. Целевая спецификация нового цикла; до завершения TASK-0033–0036 запущенная игра остаётся v3. V4 заменяет только конфликтующие правила v3, сохрает Three.js/Preact, соседний перенос и чистую модель.

## 1. Основания и границы

Пользователь требует цель 100 хексов на уровне 1, 200 на уровне 2 и далее, случайные стопки, управление только магнитом, растущие шаги и звёзды за эффективность, семь цветов, три доступных магнита и уровни с редкими крестами. Подтверждено отдельно: стопки при старте и после каждого сработавшего магнита; запрет одинаковых цветов только внутри текущей тройки, использованный цвет может вернуться.

Следующие числа — выбранный стартовый баланс автора, не измеренная сложность: 5 начальных стопок, 1/2/3 новых по стадиям ходов длиной 5×номер уровня, 6 или 12 элементов в стопке, 1–4 креста; порог очистки 6. Цвет стопки выбирается из семи равномерно; все новые стопки состоят из 2–3 непрерывных равных цветовых групп; цвета групп выбираются без замещения. Порог звёзд описан ниже. Баланс допускает последующую настройку общих констант отдельной задачей.

## 2. Поле и уровень

Общая форма: существующее odd-r поле 5×5, col/row=1…5. Данные уровня — {id, number, blockers:[{col,row}]}; number целое 1…12. Ни cells, stacks, magnets, moves, solution, goal, seed в уровне не авторятся. Валидатор проверяет ID, номер, уникальные координаты внутри общего поля, 1–4 креста и связность свободной области. Goal=50*number. Блокер запрещает placement, spawn и проход; не уничтожается. Runtime материализует cells для board из общей конфигурации.

## 3. Чистые контракты

createV4State(level, seed:uint32) создаёт immutable snapshot:
rulesVersion=4, puzzleId, levelNumber, cells, blockers, stacks (units снизу вверх), magnets (три уникальных цветовых ID), clearSize=6, goal, cleared=0, movesUsed=0, turn=0, spawnedUnits, nextUnitId, rng:uint32, seed, terminal=null, stars=0.
Не хранить remainingMoves. initialUnits — только исторический v3 термин, не знаменатель цели или граница общего притока.

Цветовые ID: violet, blue, coral сохраняются; новые gold, lime, teal, pink. Hex-палитра определяется TASK-0032, правила используют ID.

Action={type:'placeMagnet',color,cell:{col,row}}. Color однозначно обозначает один из трёх уникальных слотов.
applyV4Magnet(state,action) => {accepted,reason?,state,events,magnet?}. Ошибка действия возвращает исходный state по ссылке и пустые events: terminal, invalid-magnet, occupied-or-outside. Никаких изменений RNG, шагов, выдачи и units.

Принятый ход копирует состояние, увеличивает movesUsed и turn ровно на 1. Даже нулевой pull — принятое срабатывание. Отмена drag/промах/выбор цвета/пауза/подсказка ходом не являются.

События строго типизированы:
- unitMoved: batch, unit, from, to, fromIndex, toIndex; сохранить формат v3.
- unitsCleared: batch, cell, units (ровно 6); сохранить формат v3.
- stackSpawned: cell, units (полная новая стопка).
- magnetsChanged: before:[colors], after:[colors], used:color.
Initial spawn содержится в initial state, не повторяется событием первого хода.
Нет catch-all ветки, трактующей каждый неизвестный event как unitsCleared.

## 4. Resolve → victory → spawn/queue

1. Валидировать action/terminal и копировать state; начать временное магнитное состояние целевой пустой клетки.
2. V4: шесть прямых axial-лучей длиной до двух клеток от магнита. Поворотов/обхода нет; отсутствующая клетка, X или чужой верх обрывает луч. Ближняя подходящая группа снимается раньше дальней (равные — row,col); открывшийся чужой низ перекрывает дальнейший путь. Переносы строго соседние; legacy v3 BFS сохраняется только для исторических fixtures. Чистый kernel magnet-influence.js общий для предпросмотра и resolve.
3. При поступлении шестого matching элемента в магнитную клетку очистить ровно 6; остаток сохраняется. Пустое поле до цели НЕ победа. Промежуточные стопки не очищаются автоматически.
4. После исчерпания потока увеличить шаги, проверить cleared>=goal. Если да: terminal='won', stars рассчитать; удалить использованный магнит без refill (итоговая очередь может иметь два элемента), НЕ spawn и НЕ тратить RNG. Возвращение клетки к обычной форме — presentation, остатки остаются.
5. Если победы нет: spawn по movesUsed: 1 на ходах 1–5×N², 2 на 5×N²+1–10×N², 3 начиная с 10×N²+1, затем consume/refill тройки; события в таком же порядке. RNG спавна идёт перед RNG очереди.
6. Если после resolve/spawn нет ни одной пустой незаблокированной клетки: terminal='lost', stars=0. Приоритет победы выше поражения. Spawn может занять последнее место; нехватка мест уменьшает партию, после заполнения поля — проигрыш. Не использовать solver для определения «нет полезного хода».
7. Финальный state рассчитан синхронно; view воспроизводит события. Ввод до конца всех стадий заблокирован.

Масса: spawnedUnits = remainingUnits + cleared. Каждый созданный ID уникален за run; ID не меняется при перелёте. spawnedUnits включает старт и все пополнения. Граница итераций resolve вычисляется по числу текущих элементов, не стартовому запасу.

## 5. RNG и спавн

PRNG: uint32 LCG: rng=(Math.imul(1664525,rng)+1013904223)>>>0; u=rng/2**32. Zero seed разрешён. drawIndex(k)=floor(u*k), k>=1; при пустом выборе RNG не тратить. Взвешивание не добавлять скрыто.

Initialization: RNG=seed, сформировать тройку последовательным выбором без замещения из COLORS в стабильном порядке violet/blue/coral/gold/lime/teal/pink; затем начальный spawn 5 стопок.
Spawn: отсортировать свободные клетки row,col; count=min(requested,free.length). Для каждой новой стопки drawIndex(free.length), удалить выбранную клетку; затем height=6+6*drawIndex(2), затем groupCount=2+drawIndex(2), выбрать groupCount цветов из оставшихся без замещения; height/groupCount элементов на непрерывную группу снизу вверх. Каждый unit получает последовательный ID 'v4-u'+nextUnitId++, 2–3 разных непрерывных группы на стопку. После всех операций сортировать stacks row,col. При недостатке места уменьшить count; без reroll и без переноса существующих стопок.

Очередь: удалить used, сохранить порядок остальных; кандидаты — все 7 кроме двух оставшихся, выбрать один drawIndex(5), append. Использованный цвет снова разрешён. В presentation видны старые слоты до конца срабатывания, затем остатки сдвигаются и новый входит; model after уже хранит новую очередь. Цвета будущих стопок и магнитов не подменять ради гарантии победы.

Runtime получает новый seed через crypto.getRandomValues при первом запуске/next; retry использует исходный seed уровня этого run. URL для повторяемых browser-сценариев может задавать seed через валидированный uint32 query; это выбор начальных случайных условий, не cheat/присваивание победы. RNG никогда не зависит от FPS, reduced, hover или размера экрана.

## 6. Цель, шаги и звёзды

Goal=50*N, cleared — реально уничтоженные элементы, включая допустимое превышение: 48+6=54 на уровне 1. Progress=min(1,cleared/goal); доступное значение полосы тоже ограничено goal, текст может честно показывать 54/50.
3 звезды при movesUsed<=ceil(goal/12), 2 при <=ceil(goal/6), иначе 1 при победе. Поражение=0. Уровень 1: 3 до 5 включительно, 2 до 9, 1 с 10. Уровень 2: 3 до 9, 2 до 17. Меньше шагов не ухудшает результат. Начальный запас 30–60 и приток 6–36 за ход делают эти пороги лишь стартовой гипотезой; гарантии трёх звёзд для всех seed нет. Не переносить legacy scoring/save.

## 7. Presentation и визуальные задачи

Уточнение пользователя 2026-10-12: магнитная ячейка имеет пустой обычный центр без изображения магнита; состояние обозначается цветными светящимися бортиками и энергией по контуру. После drag handoff отдельный U-магнит исчезает, активируются бортики. По окончании бортики возвращаются к кремовым. Первые пробы с U-инкрустацией отклонены и не входят в runtime.

Порядок: drag handoff → activation → соседние unitMoved и pre-clear/packing/collection для каждой очищенной группы → deactivation → spawn → queue settle → result или playing. Конкретные durations могут быть настроены visual tasks; события и масса от них не зависят.
Цифры участвующих в текущем переносе клеток скрыты на весь интервал группы, включая stagger. Перед unitsCleared показывать 6 (именно зачисляемую группу) коротким акцентом; скрыть при packing/collection. Неучаствующие неподвижные цифры остаются.
Фишки попадают в правую кромку заполненной части полосы; displayedCleared растёт при прибытии ID, а не в начале model transition. Result появляется после последнего прибытия и восстановления обычной клетки.
Magnetic tile, blocked tile и 7-color assets — отдельные задачи; слой логотипа, цельный фон/idle и исправление артефактов также выполняются по очереди.
Один runtime RAF/fixed step; paused/hidden замораживают время и отменяют жест; reset/dispose удаляют presentation. Reduced motion сохраняет те же события/итог, сокращает стадии и не использует экранный перелёт/частицы.
