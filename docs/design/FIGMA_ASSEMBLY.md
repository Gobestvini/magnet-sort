# Magnet Sort — точная сборка мокапов в Figma

2026-10-10. Пользователь отклонил векторную перерисовку, поскольку она меняла форму, масштаб, материалы и композицию. Актуальный источник — 12 PNG English revision 2 в `docs/design/mockups/2026-10-09-facebook-casual/`.

[Файл Figma](https://www.figma.com/design/Nntj95XfGJSGVy0FwadZMN?node-id=5-4448). Актуальная страница: **01 Exact mockup slices**. Все 12 фреймов 941 × 1672 импортированы через обычный браузерный редактор, координаты сетки: `x = (index % 4) × 1061`, `y = floor(index / 4) × 1832`. Предыдущая перерисовка сохранена на странице **Archive — approximate reconstruction** и не является источником дизайна.

## Что изменилось

- 615 отдельных PNG-слоёв вырезаны заново из оригиналов без изменения масштаба и цветов. Логотипы, рамки, кнопки, иконки, магниты, видимые части плиток/колец, надписи и эффекты сохраняют исходное оформление.
- В Figma слои сгруппированы по назначению: Header, HUD, Board, Pieces, Tools, Actions, Pause, Victory и другие. Это растровые ассеты, не native text и не библиотека component instances.
- Рисованные надписи сохранены как изображения: обычный Nunito не воспроизводил оригинальные буквы, блики и тени. Нельзя менять цифры как текст внутри этих изображений.
- Фон содержит только оставшуюся видимую часть исходного фона, с прозрачными местами под извлечёнными объектами. Полный растровый экран не используется как подложка или слой фрейма.
- Двухпиксельный запас исходных цветов по краям уменьшает швы при масштабировании. Перекрытия содержат одинаковые исходные пиксели.

## Воспроизведение

Нужны Python, Pillow, NumPy. Из корня проекта:

```powershell
python tools/slice-exact-figma.py
python tools/verify-exact-figma.py
```

Результат: `artifacts/figma-exact/`.

- `01-loading/` … `12-render-error/` — исходные PNG-вырезки с прозрачностью.
- `manifest.json` — имена, координаты, размеры, роли и SHA-256 всех вырезок и исходников.
- `01-loading.svg` … `12-render-error.svg` — самостоятельные импортные файлы со встроенными PNG и именованными группами. `python tools/slice-exact-figma.py --svg-only` пересобирает только SVG из проверенного manifest.
- `index.html` — локальная галерея `/artifacts/figma-exact/index.html`.
- `verification.json` — независимая проверка PNG на диске и фактических SVG payload.
- `reassembled.png` в папке каждого экрана — только контрольная локальная сборка; эти полные изображения в Figma не импортировались.
- `figma-all-screens.jpg`, `figma-playing.jpg`, `figma-victory.jpg` — подтверждение результата непосредственно в Figma.
- `artifacts/magnet-sort-exact-slices.zip` — пакет новой нарезки, manifest, SVG и инструкции.

Импорт: Figma **Place image → выбрать SVG → Place all**. Не импортировать контрольный `reassembled.png`. Текущий MCP лимит Starter не препятствует этому обычному действию редактора.

## Проверки и точность

Независимый проверяющий скрипт прочитал 615 PNG с диска, проверил их SHA-256, размеры, координаты и содержимое встроенных PNG в SVG. Сборка каждого из 12 экранов имеет **нулевую разницу каналов RGBA** относительно оригинала.

Дополнительно через интерфейс Figma экспортированы все 12 фреймов в PNG 1×. Их размеры — 941 × 1672. Экспорт Figma не равен исходным байтам: средняя абсолютная разница канала составляет 0.075–0.181 из 255; максимальная локальная разница — 51 из 255. Причина этой обработки растра редактором не установлена; нулевое попиксельное отличие экспорта Figma не заявляется. Геометрия, оригинальная графика и композиция сохранены; все состояния просмотрены в общей сетке, игра, победа и пауза проверены крупно.

Повторить сравнение фактического экспорта:

```powershell
python tools/verify-exact-figma.py --figma-export 'C:/path/to/export.zip'
```

## Граница подготовки к игре

Это точная сборка видимых пикселей мокапов. У перекрытых объектов вырезаны только видимые области; плитки разделены по границам видимых областей, полосы колец отражают рисунок исходника, а не количество элементов игровой модели. Рамки имеют отверстия на месте извлечённых надписей/иконок. Такие части нельзя объявлять готовым универсальным nine-slice или неограниченно перемещать по полю.

Перед runtime-переносом потребуется восстановить скрытые части, собрать чистые повторяемые плитки/кольца/рамки и обеспечить живые счётчики. Эту работу нужно сверять с текущей точной композицией. В этом запросе runtime и прежние `public/art/mockup/` не изменялись; задача — переделать Figma и заново нарезать оригинальную графику.

`tools/build-figma-screens.cjs` и `tools/figma-screen-importer.js` относятся к архивной приближённой сборке; их векторные примитивы не используются на актуальной странице.
