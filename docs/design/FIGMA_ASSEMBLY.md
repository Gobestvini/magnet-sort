# Magnet Sort — сборка экранов в Figma

2026-10-10. Источник: 12 утверждённых English revision 2 мокапов. Текущая игра пользователю не подходит из-за геометрии поля и артефактов. Следующая реализация должна начинаться с согласованной сборки экранов и компонентов в Figma.

Файл создан: https://www.figma.com/design/Nntj95XfGJSGVy0FwadZMN

**Статус: файл пока пуст.** При обнаружении библиотек Figma вернула исчерпание лимита MCP на Starter. Запись экранов и проверка результата в Figma не выполнены. Офлайн-пакет подготовлен отдельно; это не подтверждение успешного импорта.

## Что подготовлено

- 12 композиций 941 × 1672: загрузка, обучение, игра, допустимое/недопустимое размещение, перелёт, очистка, подсказка, пауза, победа, поражение, ошибка запуска.
- Общие редактируемые векторные клетки, кольца, панели, рамки, кнопки, иконки и эффекты. Логотип, фон и магниты используют отдельные исходные PNG. Полные скриншоты интерфейса не используются как слои экранов.
- Английский текст. В импортере это настоящие текстовые слои Nunito Black; магнитам не добавляются символы.
- Единая point-up геометрия: ширина hex 160, высота `2 × 160 / sqrt(3) × 0.78`, шаг рядов `0.75 × height`, смещение нечётных рядов 80. Все 56 общих рёбер 25 клеток имеют совпадающие концы. Внешний контур не уменьшается ради обводки: фаски расположены внутри.
- Кольцо использует тот же контур при ширине 116; один слой имеет толщину 16. Стопка из шести колец содержит шесть отдельных экземпляров; одного PNG с нарисованной стопкой нет.

Это новая сборка на основе мокапов с исправленной геометрией, а не обещание полного пиксельного совпадения с иллюстративным полем.

## Воспроизведение и импорт

Из корня проекта: `node tools/build-figma-screens.cjs`.

Результаты находятся в `artifacts/figma-casual/`:

- `index.html` — галерея всех экранов; удобнее открыть через dev server `/artifacts/figma-casual/index.html`.
- `design.json` — слои, компоненты, размеры и тексты без встроенных битмапов.
- `01-loading.svg` … `12-render-error.svg` — SVG-превью с отдельными текстовыми/векторными элементами. PNG и шрифт берутся из соседней папки `assets`; SVG в одиночку не является переносимым файлом со всеми изображениями.
- `figma-plugin/manifest.json` и `code.js` — стандартный development plugin для ручного импорта. Битмапы встроены один раз в код; сеть не используется. Создаются новые страницы `00 Components` и `01 Screens`, существующие страницы не удаляются. Повторный запуск создаёт ещё один набор страниц.

Для ручного импорта сначала создай development plugin в редакторе Figma, чтобы получить назначенный Figma `id`; затем замени его `code.js` подготовленным файлом и сохрани свой `id` при переносе остальных полей manifest. Альтернатива: задай `FIGMA_PLUGIN_ID` полученным значением и повтори сборку — тогда подготовленный manifest можно импортировать напрямую. Произвольный выдуманный ID не используется. [Документация manifest](https://developers.figma.com/docs/plugins/manifest/), [создание development plugin](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-plugin-for-development).

Если этот способ недоступен в твоём редакторе/тарифе, используй тот же пакет для последующей записи через MCP после восстановления лимита. Агент не запускал плагин для обхода лимита сервиса. Если Nunito Black недоступен, импорт останавливается до изменения документа.

После импорта необходимо проверить в Figma: 12 экранов, доступность текста для редактирования, изображения без пустых мест, целые обводки, точные стыки клеток, шесть отдельных колец и отсутствие обрезания модальных окон. Успешная генерация офлайн-пакета не заменяет эту проверку.

## Выполненные проверки

`node tools/build-figma-screens.cjs` проверяет совпадение 56 общих рёбер и сохранение суммы видимых/очищенных элементов во всех игровых состояниях. В кадре перелёта 17 элементов в стопках и один в воздухе; в очистке — шесть ещё видимых и 12 уже очищенных. Эти композиции показывают состояния интерфейса, а не являются записью решения текущего уровня.

`GAME_BASE_URL=http://127.0.0.1:5174 node tools/figma-preview-check.cjs` проверяет 12 SVG-композиций, декодирование 61 использования PNG, наличие градиентов, Nunito и отсутствие текста вне экрана. Результат: ошибок нет. Снимки `gallery.png`, `03-playing-preview.png`, `09-paused-preview.png`, `10-victory-preview.png`, `11-defeat-preview.png` сохраняются рядом с пакетом. Это браузерное превью; native Figma import ещё не проверен.

`node --check artifacts/figma-casual/figma-plugin/code.js` проверяет синтаксис подготовленного плагина. Для проекта также выполнен `pnpm check:full`.

## Последующий перенос в игру

1. Проверить сборку в Figma и согласовать геометрию/внешний вид.
2. Экспортировать цельную клетку и одно кольцо с одинаковой проекцией; зафиксировать опорные точки и толщину. Рамки экспортировать с согласованными nine-slice границами; контуры не обрезать trim по-разному.
3. Перенести компоненты и формулы сетки, затем сравнить реальные кадры каждого состояния с Figma.
4. Проверить совпадение числа слоёв с моделью, ввод, перелёт, resize и реальные устройства. Не заявлять соответствие только на основании unit-тестов.

В этой работе runtime не изменяется: перенос в игру следует после проверки Figma, согласно запросу пользователя.
