# Паспорт новой игры

Заполни до выбора движка и крупных изменений. Сейчас это пустой шаблон; значения ниже требуют решения для новой игры.

- Игрок и основное действие: casual puzzle игрок выбирает цветной магнит и ставит его на пустую клетку hex-поля; фишки выбранного цвета притягиваются, объединяются и очищаются.
- Цель, победа/поражение, длительность сессии: очистить указанную массу или поле; поражение по исчерпанию лимита без победы либо отсутствию legal placement. GDD задаёт сессию 20–60 секунд как гипотезу, не измеренную цель.
- Первый играбельный срез: одно размещение → детерминированные волны pull/merge/clear → результат → retry. Пошаговые волны до покоя выбраны для прототипа, чтобы поддержать chain reaction.
- Целевые устройства, браузеры/платформы, ввод: baseline для проверки — Android 13+, Chrome stable, Pixel 6a, portrait/touch; desktop Chromium — разработка и регрессии. Фактическая доступность устройства не подтверждена. Facebook Instant Games остаётся платформенной гипотезой до отдельного исследования.
- Визуальная и звуковая концепция, референсы: псевдо‑2.5D на PixiJS 8; hex-поле, фишки и магнит получают объём слоями, фасками, бликами, тенями и анимацией, без настоящей 3D-сцены. Светлый тёплый фон, коралловый/синий/жёлтый/мятный; формы/символы дополняют цвет. Уточнения — `design/GDD_V0.2.md`, renderer contract — `design/PIXI_RENDERING.md`; референсы не являются лицензированными ассетами.
- Ограничения и то, что не входит в первый срез: без physics engine, meta, monetization, социального SDK и массовой кампании до прототипного go/no-go. Первые 5 tutorial levels должны подтвердить понятность и желание повторить.
- Целевой renderer: PixiJS 8.22.0 для псевдо‑2.5D игрового поля; Preact 11.0.0 остаётся DOM HUD, pure JavaScript simulator отдельно. Один runtime владеет RAF; второй ticker не запускается.

## Измеримые бюджеты

Запиши целевое устройство и одинаковый сценарий до/после. Выбери целевую частоту: например 60 FPS даёт 16.7 мс на кадр, 30 FPS — 33.3 мс. Это арифметика бюджета, а не измерение мощности устройства.

| Метрика | Цель новой игры | Как измерять |
| --- | --- | --- |
| p95 времени кадра | цель <16.7 мс на baseline 60 Hz | устройство, версия, прогрев, длительность |
| CPU симуляции / render | определить | отдельные замеры; CPU render не GPU |
| Загрузка / вес | определить | cold load, сеть, compressed transfer |
| Память и ресурсы | определить | baseline и серия reset/смен сцен |
| Задержка ввода | первый отзыв в пределах 150–300 мс по GDD | реальное устройство, повторяемое действие |

Все значения — цели, не замеры. Методика и ограничения — `design/ARCHITECTURE.md`; проверить 20 одинаковых действий на точной модели телефона, записав OS/browser/build и p95. Не выдавать эмуляцию за физическое устройство.

Не заполняй FPS, RAM и число объектов произвольными «универсальными» лимитами.
