# Magnet Sort — паспорт 3D-прототипа

Актуально на 2026-10-09. Дизайн: [GDD v0.3](design/GDD_V0.3.md); rendering/lifecycle: [THREE_RENDERING](design/THREE_RENDERING.md).

- Игрок — любитель коротких casual puzzles. Основное действие: выбрать магнит и поставить его на пустую hex-клетку касанием или перетаскиванием. Стопки уже находятся на поле.
- Payoff — быстрая цепочка: верхние элементы выбранного цвета переворачиваются по одному в соседнюю клетку, собираются у магнита и очищаются группами по 6. Смешанная стопка открывает нижний цвет. Движение основано на приложенном видео; конкретные magnet rules и порог — решения нашего прототипа.
- Победа — убрать все элементы в пределах лимита размещений. Поражение — исчерпаны ходы без победы либо нет свободной клетки. Сессия 20–60 секунд остаётся гипотезой; в коротком прототипе длительность не подтверждена исследованием.
- Играбельный срез — три авторских поля, ordinary/reduced motion, tap/drag/keyboard, hint, pause/resume, reset/retry, победа/поражение и переход дальше. Новые правила обозначены `rulesVersion: 3`.
- Визуальный стиль — настоящее 3D на Three.js 0.186.1, светлые объёмные hex-плитки и отдельные цветные кольца, фиксированная наклонная ортографическая камера, простые материалы/свет/тени. Тёмный спокойный фон и фиолетовый/голубой/коралловый с дополнительными символами. Preact DOM сохраняет читаемый HUD.
- Архитектура — pure JS model, unit events и pure presentation timeline; один app-owned RAF/fixed step, raycast input и явное освобождение GPU-ресурсов.
- Прежний PixiJS MVP и 50 уровней сохранены как legacy. Новый entry не использует прежние progress/daily/challenge/scoring/platform/ads/audio и не меняет старые сохранения. Их перенос зависит от окончательного выбора правил v3.
- За границами среза — physics engine, свободная камера, несколько постоянных магнитов, новая массовая кампания, монетизация, аккаунты, публикация и Telegram.

## Устройства и бюджеты

Baseline для будущего реального замера — Pixel 6a, Android 13+, Chrome stable, portrait/touch. Desktop Chromium и mobile/landscape viewport — browser surrogates. В этом запросе физический телефон не предоставлен и не проверен.

| Метрика | Цель | Проверка |
| --- | --- | --- |
| p95 frame | <16.7 мс на baseline 60 Hz | Реальное устройство, тот же уровень/цепочка, прогрев и 60 с повтора |
| Первый отзыв | Подсветка/магнит в ближайшем render после pointer; предел прежней гипотезы 150–300 мс | Action-to-feedback на телефоне, отдельно от полной длительности цепочки |
| CPU model/render | Пока нет измеренного бюджета | Отдельные замеры, CPU render не называть GPU time |
| Загрузка/transfer | Пока нет утверждённого бюджета | Cold load, сеть, compressed transfer |
| Ресурсы | Reset не накапливает geometry/renderer/listeners | 20 повторов, renderer.info и dispose; отдельно реальная память |

Все численные бюджеты — цели. DPR cap 2 и shadow map 1024 — текущие настройки, не доказательство 60 FPS. Старые waivers/отчёты MVP не являются приёмкой v3. Фактические проверки и непроверенные критерии: [THREE_PROTOTYPE](reports/THREE_PROTOTYPE.md).
