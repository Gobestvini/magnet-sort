## 4. Требуемое поведение

Предложение автора по объёму: сохранить 1–3, добавить 4–12 в три группы по три поля. Уровни 4–6 вводят ограничение порядка двух цветов и маршруты; 7–9 — смешанные стопки/открытие цвета и blocker-коридоры; 10–12 — совместный выбор порядка, позиции и тесного лимита. Использовать существующие три цвета и порог 6. Английские title/subtitle/lesson коротко объясняют текущую механику.
Для каждого нового поля нужны минимум три различные выигрышные последовательности в пределах moves; минимум две различаются выбором первого полезного хода (цветом или клеткой). Не считать добавленные бесполезные ходы или перестановку независимых действий единственным доказательством разнообразия: документировать хотя бы одну пару, меняющую промежуточные маршруты/открытие слоёв.
Каждое новое поле должно иметь достижимую значимую проигрышную развилку: из одного состояния полезный legal ход ведёт к выигрышному продолжению, другой legal ход двигает/собирает элементы, но делает победу невозможной в оставшемся лимите. Не считать единственным «неправильным» действием клик цветом, который ничего не двигает. Не требовать немедленного game over: текущая модель объявляет lost при исчерпании ходов/свободных клеток.
Доказательства строить исчерпывающим bounded DFS/BFS по applyMagnet с мемоизацией и безопасным ключом состояния. Для false-win ветки перебрать все допустимые продолжения; превышение бюджета поиска означает unknown, а не доказанный тупик. Не вводить эвристическое pruning без доказательства. Сохранять ID в runtime, а ключ поиска может нормализовать равнозначные units одного цвета при обосновании эквивалентности.
На каждое поле сохранить три win witnesses и prefix + good/bad action для развилки, результат полного поиска bad-ветки, число состояний и время проверки. Сложность обосновать минимум числом минимальных полезных ходов, зависимостями открываемых цветов и долей проигрышных первых полезных ходов. Группы должны демонстрировать рост, без требования строго монотонного роста всех метрик на каждом поле. Пройти вручную, поскольку solver не доказывает интересность.
