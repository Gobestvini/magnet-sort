## 3. Область изменений

Новый PNG blocked tile, assets.js/buildLevel и профильная документация/проверки. Не менять blocker coordinates, правила маршрутизации, уровни и цветовую палитру. Старые shared ресурсы удалить только если точно больше не используются.

Для рендера/ввода/ресурсов сначала сверить docs/design/THREE_RENDERING.md (§§ «Владение», «Рендер и ввод», «Lifecycle и стоимость»). docs/design/PIXI_RENDERING.md явно legacy; из docs/knowledge/pixijs-practices.md применить переносимые §§ «Сцена и владельцы», «Ввод и hit testing», «Ассеты и загрузка», «Производительность и графика», «Lifecycle и качество», без Pixi API в Three runtime. Применять game-quality; для генерации PNG — imagegen; для объёмного контекста — ai-economy.

## 4. Требуемое поведение

Новая клетка — самостоятельный узнаваемый тайл X с объёмом и контуром обычной клетки, одинаковой камерой, светом и масштабом. Предложение автора: приглушённая серая встроенная поверхность с ясным X; без чёрных кайм и наложенного двойного бортика. Заменить составной renderer одним согласованным вариантом, не просто добавить ещё один X поверх. Сохранить blocker semantics и запрет размещения/пути; raycast продолжает возвращать правильный cell. Ассет прозрачный, загрузка через BASE_URL и существующий retry/dispose.

Сохранять английский пользовательский интерфейс, pause/reset/hidden/dispose, доступный tap/drag/keyboard и reduced motion в применимой области.
