## 4. Требуемое поведение

1. Сравнить A=current goal50*N/cadence1,2,3; B=goal30+10*N с нынешним cadence; C=goal как B, cadence1 на L1–6 и2 на L7–12. Остальные правила: 5 стартовых стопок, 6/10, clear10, цвета/группы/X/радиусы и пороги партий 5*N²/10*N² сохраняются. Это кандидаты автора, не выбранные пользователем настройки.
2. Экспериментальный профиль должен управлять goal/cadence через общий kernel; не менять глобальный Math.random, не monkey-patch замкнутые функции. Default A сохраняет побайтово одинаковые state/events для контрольных seeds/actions.
3. По каждому варианту: уровни1–12 × seeds0…49 × greedy/random; cutoff320, timeout отдельно. Вывести win/lost/unknown, median/p90 moves побед, число звёзд, min free, исходный SHA/профиль/версию. На вариант и уровень сохранить минимум 3 победных replay-witness при наличии; отсутствие witness честно отметить.
4. Не подбирать индивидуальный seed только для красивого отчёта. Одинаковый seed не гарантирует одинаковую RNG-трассу после различного числа spawn; это свойство эксперимента отразить.
5. Для звёзд показать текущую формулу и предложенные отдельные пороги moves по победным распределениям. Порог — ориентир, не сертификат оптимальности/трёх звёзд для каждого seed. Признак помощи не смешивать с числом ходов.
6. Человеческий playtest: минимум два добровольных игрока, по одной ранней/средней/поздней партии лучшего кандидата и A, порядок чередовать. Фиксировать активное время, idle отдельно, ходы, поражения, понимание спавна и желание повторить. Цель-гипотеза обычной партии2–4мин, daily1–3мин без таймера.
7. Если люди/физический телефон недоступны, завершить техническую часть и оставить review: не заменять их greedy или viewport. Результат исследования может рекомендовать дополнительный вариант; не запускать бесконечный подбор и не внедрять его без отдельного решения.
