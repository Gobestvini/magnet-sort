## 1. Цель и запрос пользователя

«Нужно не так много спавнить новые стеки на поле, а регулировать спавн в зависимости от количества ходов: чем больше ходов, тем больше идёт спавн; если на поле нет места, показывается экран проигрыша».

Результат: спокойное начало и растущее давление спавна; заполнение всех доступных клеток завершает попытку поражением.

Предложение автора, а не заданные пользователем числа: 5 стартовых стопок вместо 7; после принятого хода на уровне N с movesUsed 1–5×N² появляется 1 стопка, 5×N²+1–10×N² — 2, начиная с 10×N²+1 — 3. Пользователь 2026-10-12 выбрал «Замедлить рост на поздних уровнях» после проверки первых маршрутов; растяжение стадий по N реализует это решение. Верхний предел 3. Это начальный баланс для проверки, не обещание оптимального баланса.

## 4. Требуемое поведение

- Политика спавна — чистая функция от числа уже принятых ходов; initial spawn задаётся отдельно. Невалидные placement/drag cancel/pause не тратят ход, RNG и не вызывают спавн.
- После pull/clear и увеличения movesUsed сначала проверить цель: победа имеет приоритет; при победе нет спавна, refill и поражения.
- В непобедном ходе спавнить min(запрошено, число свободных legal-клеток), разрешая последнюю. Занятые клетки и кресты не перезаписывать. Нехватка мест для полной партии сама по себе не ошибка: разместить доступную часть; если после этого не осталось legal-клеток — terminal=lost, stars=0.
- При отсутствии свободных клеток не вызывать drawIndex с нулём; не добавлять случайных draws ради отсутствующих стопок. Проверка lost обязательна и при нулевом спавне после pull.
- Сохранить ID/массу units, immutable вход applyV4Magnet, RNG в state и воспроизводимость одинаковых seed+actions. Retry восстанавливает старт, movesUsed=0, terminal=null.
- UI блокирует дальнейшие действия после terminal; проигрыш появляется один раз после завершения presentation, с причиной заполнения поля и рабочим Try again. До TASK-0050 использовать текущий экран.
