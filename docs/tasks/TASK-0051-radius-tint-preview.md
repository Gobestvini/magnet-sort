## 1. Цель и запрос пользователя

«Выделение ячеек при переносе магнита не нравится… может тинтом подсвечивать ячейки через моргания… все ячейки по кругу от ячейки с магнитом на два поля… попробуй сгенерить, как это выглядит, и я скажу, норм или нет».

Уточнение пользователя 2026-10-12: «не нравится подсветка на макете; должен подсвечиваться только бордер у всех ячеек; если магнит синий, то синим светом, моргая мягко по очереди: сначала один круг, потом второй и так далее в айдл цикле».

Наблюдаемый результат: светятся только бортики отдельных ячеек цветом выбранного магнита. Сначала мягко вспыхивает и гаснет первое кольцо соседей, затем второе; цикл 1→2→1→2 повторяется, пока preview активен, даже при неподвижном указателе. Заливки поверхности нет. Одобренная проба: `docs/design/border-preview-v2/concept.png`, промпт/ограничения в `PROMPT.md`. Старый v1 сохранён как отклонённая история. Новый макет — статический storyboard двух фаз, одобрен пользователем 2026-10-12, но ещё не перенесён в игру.

## 4. Требуемое поведение после согласования

- Геометрия: ring1 — все клетки state.cells с hexDistance(center, cell)=1 (до 6), ring2 — с distance=2 (до 12). Края обрезаются границами поля, центр не входит в кольца. Светится бортик каждой клетки кольца, а не один общий контур вокруг всей зоны. Это декоративная зона, не обещание pull из каждой клетки.
- Центр должен быть legal пустой клеткой. Бортики подсвечивать у всех ячеек обоих колец, включая занятые стопками и кресты: не перекрашивать chips/X и не нарушать их естественное перекрытие бортика. Blocker не становится legal и продолжает блокировать actual pull. Не строить BFS в обход препятствий.
- Заливка, внутреннее углубление, фишки и кресты сохраняют исходные цвета. Цвет света бортика = цвет выбранного магнита, у синего — синий. Узкий мягкий ореол допустим вокруг бортика, но без широкого пятна, окрашивающего всю ячейку; сохранять её фаску/объём.
- По очереди пульсируют целые кольца, не отдельные клетки по часовой стрелке. Предложение тайминга: полный цикл 2.4s, две фазы по 1.2s. Первая: ring1 мягко поднимает яркость от 0 и гаснет, ring2 не светится; вторая — наоборот. Можно sin²-профиль с нулевой производной на краях, без резких вспышек. После второй фазы начинается первая; третьего кольца нет, исходный радиус 2 сохраняется.
- Убрать конкурирующие прежние drag-частицы/контуры/halo; actual work waves/particles после размещения сохранить. Неверная/занятая цель и указатель вне поля не показывают кольца. Смена цели начинает цикл с ring1, смена цвета обновляет свет без следов старого оттенка.
- Preview доступен при текущих drag, tap-to-place и keyboard candidate согласно модели ввода; не добавлять hover-зону без выбранного магнита. Idle здесь означает повтор при неподвижной активной цели, а не подсветку всего поля без магнита. Reduced motion — оба кольца со статичным умеренным светом бортиков, без пульсации.
- Время берётся из app runtime; обеспечить продолжение существующего RAF при активном preview без drag/timeline (tap/keyboard), и остановку после очистки preview. Не создавать отдельный RAF/timer. Pause/hidden замораживают/скрывают корректно, resume без скачка. Cancel, release, lost capture, reset, blur/resize/dispose и terminal убирают preview. Не мутировать общий материал так, чтобы окрасились бортики вне маски. Ресурсы фиксированы/переиспользуются и освобождаются board.
