## 4. Требуемое поведение

Предложение автора: один burst из двух нижних боковых зон вокруг панели; 32–48 частиц, жёсткий максимум 48 живых DOM-узлов. Спавн короткими волнами в первые 250–400 мс, движение вверх и наружу, затем вниз с вращением и угасанием. Lifetime 900–1600 мс, весь эффект заканчивается не позже 2 с. Звёзды можно включить в тот же движущийся burst; фиксированные static star/confetti удалить. Частицы стартуют у эмиттера, а не уже разбросанными по экрану.
Предпочтительная реализация: заранее вычисленные seeded траектории/задержки и CSS keyframes либо Web Animations API с отменой при unmount. Второй RAF или interval не добавлять. Не расширять runtime RAF ради декларативного CSS эффекта. CSS variables задают точки дуги/вращения; transform/opacity без покадровой записи layout. Слой pointer-events:none, aria-hidden, позади текста и кнопок результата; обрезать у viewport без горизонтального скролла.
Burst запускается ровно один раз на переход к новой победе после окончания collection. Ререндер/resize не создают новый burst. Next/Replay/Reset/unmount/dispose отменяют эффект и удаляют DOM/animation handles; повторная победа создаёт свежий burst. Hidden замораживает или отменяет оставшийся эффект (выбрать отмену как простой вариант); возвращение не запускает его снова. Не ждать animationend для разблокировки Next.
При reduced=true или prefers-reduced-motion нет летящих, вращающихся или статичных частиц; сам результат остаётся читаемым. При defeat, pause, loading и error частицы не появляются. В отчёте указать максимальное количество узлов и отсутствие роста после 20 циклов победа → Replay/Next.
