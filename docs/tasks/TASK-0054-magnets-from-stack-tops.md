## 4. Требуемое поведение

Предложение автора: до трёх уникальных магнитов; если открытых цветов только один или два, показывать соответственно один или два. Не добавлять бесполезный цвет и не дублировать кнопки одного цвета. Это явная замена прежнего контракта «всегда три», необходимая для строгого выбора по верхушкам.
Сначала initial spawn, затем queue. После принятого нев winning хода — resolve, spawn по прежнему расписанию, затем пересчитать открытые цвета. Сохранять порядок оставшихся магнитов только если их цвет всё ещё открыт; удалять устаревшие, выбирать недостающие seeded без замещения среди topColor непустых стопок. Открытые цвета — уникальные вершины, не все внутренние слои. Каждый выданный магнит входит в палитру уровня.
Если стопок совсем нет до цели, разрешён fallback: до трёх цветов текущей палитры, чтобы ходы могли дойти до следующего spawn. Явно протестировать и документировать исключение. Если нет свободных клеток — прежний lost; не выдавать это за отсутствие полезного цвета. Цвет сверху не гарантирует доступность маршрута: запретить обещать полезность каждого placement.
Winning ход не spawn/refill, не тратит RNG и сохраняет прежний результат. Отмена/промах/preview не меняют queue/RNG. Если selected исчез, выбрать первый доступный; input и tray никогда не показывают старую очередь после её смены. Сохранить consume по color, уникальность, сдвиг retained и возможность повторной выдачи использованного цвета при наличии сверху.
