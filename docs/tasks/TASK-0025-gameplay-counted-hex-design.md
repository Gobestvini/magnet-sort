## 1. Цель и запрос пользователя

Переработать **один главный игровой экран** в существующем файле Figma. На поле должны быть тонкие, точно вписанные в клетки hex-фишки; цифра показывает количество элементов непрерывной верхней группы одного цвета. Видимые слои и перелёты соответствуют реальным элементам списка, без декоративных дополнительных слоёв. Проверить движение в небольшом отдельном Three.js motion-preview того же поля.

Исходный запрос: «давай переделаем макет один с главным гейплеем», показать цифрой количество хексов последнего цвета, сделать фишки тонкими, показывать и переносить ровно логическое количество, обеспечить логичную приятную анимацию и точную посадку в клетки; посмотреть конкурентов. Пользователь приложил два кадра Hexagon Puzzle Quest.

Предложенные автором решения: трактовать «последний цвет» как непрерывную группу сверху, а не все вхождения цвета; использовать сплошную верхнюю грань тонкой фишки по приложенному референсу вместо прежнего кольца с отверстием; для проверки анимации сделать отдельный preview, поскольку статичный Figma-кадр не доказывает корректность перелётов. Это визуальное исследование одного экрана, а не перенос нового дизайна во всю игру.

Пример: список снизу вверх `[blue, blue, violet, violet, violet]` → пять отдельных фишек и цифра **3**. После ухода верхних трёх открывается синяя группа с цифрой **2**. `[violet, blue, violet]` → цифра **1**.

## 4. Требуемое поведение

### Геометрия и количество

1. Один `unit.id` → одна отдельная фишка. Высота определяется индексом и постоянной толщиной; запрещены лимит видимых слоёв, нарисованные дополнительные полосы и скрытое уменьшение числа mesh.
2. Для нового варианта использовать flat-top сплошной hex, как в приложенном gameplay-кадре. Клетка, фишка, фаска, тень и hit area используют один hex-контур и согласованную камеру/проекцию. Ориентация визуального поля не меняет IDs и соседство модели.
3. Начальная толщина — 3–5% ширины фишки; это авторская стартовая настройка, не измерение конкурента. В fixture из 20 элементов вся стопка помещается в игровой области, верхняя цифра читается; толщину финально записать. Нельзя обрезать или объединять элементы для прохождения проверки.
4. Центр посадки совпадает с проекцией центра целевой клетки с погрешностью не более 1 CSS px. Верхняя грань имеет равномерный inset относительно клетки; соседние плитки образуют общую сетку с одинаковыми стыками. Нет случайных щелей, двойных граней, разной ориентации, z-fighting или пересечений фишек после посадки. Боковина высокой стопки может закономерно закрывать часть клетки позади неё.

### Цифра

5. `topRunCount(units)` считает только непрерывную верхнюю группу; пустая стопка → счётчика нет. Цифра над верхней гранью, контрастная, минимум 16 CSS px при ширине 390, с обводкой/тенью; варианты 1, 6, 12 и 20 не обрезаются. В Figma новый счётчик — редактируемый текст, в preview — динамическое значение, не PNG с фиксированной цифрой.
6. В покое значение рассчитано из списка. Во время движения — из текущих осевших элементов presentation: источник уменьшается при взлёте, приёмник увеличивается при посадке, летящая фишка не считается в двух стопках. При открытии другого цвета цифра меняется на новую верхнюю группу. При очистке исчезает вместе с очищаемой группой; итоговый state не показывается раньше timeline.

### Движение и preview

7. Использовать `applyMagnet` → события → timeline/sampler. Летит ровно указанный событием `unit.id`, по одному элементу, сверху источника на вершину соседнего приёмника, с верными fromIndex/toIndex. Не перемещать всю группу как одну картинку и не прятать лишние элементы при старте.
8. Число перелётов равно числу `unitMoved`, а не обязательно числу уникальных ID: один элемент может пройти несколько соседних рёбер. Для одного ID перелёты последовательны. В каждый момент ID находится ровно в одной фазе: покой / полёт / очистка / уже очищен; суммарное число сохраняется.
9. Быстрая волна: короткий подъём, плавная дуга, аккуратный flip, мягкое торможение и небольшая посадочная отдача без сдвига итогового центра. Стартовать от текущих 0.19 s и 0.055 s; финальные параметры записать. Траектории/разведение по времени не допускают видимых проходов через соседнюю стопку. После посадки наклон и масштаб возвращаются к исходным. Reduced motion убирает flip/дугу/отдачу, сохраняя порядок и количество.
10. Preview отдельной страницей имеет Play/Pause, Replay, scrub времени и выбор проверяемого fixture. Исходное и конечное состояния показываются из данных; scrub воспроизводим в обе стороны. Режимы: одиночный перенос, верхняя группа смешанной стопки, цепочка из нескольких соседних клеток, очистка, высокая стопка 20 элементов. Цепочку/очистку строить из реальных событий модели, не рисовать вручную.
11. Один владелец RAF; pause/hidden останавливают время, replay сбрасывает presentation, dispose освобождает ресурсы. Preview не запускает production app параллельно. Визуальный экран рассчитан на portrait 390×844; проверить 320×640 и 430×932 без обрезания поля, цифр и магнитов. Figma основной экспорт 941×1672 сохраняет casual-композицию; адаптация viewport может добавлять вертикальные отступы.
