## 1. Цель и запрос пользователя

Исходный запрос: «нужно написать музыку и звки для всей игры и добавить кнопки на паузе по их нестройке».

Результат: активная игра получает оригинальную фоновую музыку и согласованный набор эффектов для всех существующих взаимодействий. В паузе игрок раздельно включает музыку и звуки, регулирует их громкость; выбор сохраняется после перезагрузки.

Сейчас → после: в текущем Three.js runtime нет звука, а на паузе только Resume/Restart → после первого действия пользователя звучит спокойная музыка, события получают своевременные эффекты, на паузе доступны Music/Sounds и громкость каждого канала.

Предложенные автором решения, не отдельные требования пользователя: один общий музыкальный цикл для всех 12 уровней; оригинальная партитура и синтез Web Audio без внешних записей, платных сервисов и новой библиотеки; два независимых переключателя и два регулятора громкости. Это одна цель — законченный управляемый звук активной игры. Перенос legacy Home/social/haptics не требуется.

## 4. Требуемое поведение

### 4.1. Музыка и звуковой дизайн

Сочинить оригинальный спокойный instrumental casual puzzle loop: предложенный ориентир — 32 такта, 4/4, 96 BPM (80 секунд), мажорная гармония, мягкий mallet/pluck, тихая подкладка и лёгкая перкуссия. Нужны различимые фразы A/B, развитие и возврат без заметного шва; один повторяющийся тон или случайный набор beep не считается композицией. Партитура/патчи хранятся в исходниках воспроизводимо; описать длительность, темп, голоса и происхождение в ASSETS. Без вокала, чужих мелодий/сэмплов и резких высокочастотных сигналов. Эквивалентная авторская композиция допустима с описанием отличий в отчёте.

| Событие активной игры | Обязательный слышимый отклик и момент |
| --- | --- |
| UI: Pause/Resume/close, Restart, Next level/Play again/Try again, retry после ошибки | Короткий мягкий click, один раз на действие. Изменение volume не должно генерировать очередь кликов. |
| Выбор магнита мышью/touch/клавиатурой, начало drag | Один короткий select; pointerdown+click одного выбора не дублируют его. Hover/pointermove молчат. |
| Установка на свободную клетку | Короткая посадка/магнитный pulse после accepted; работает и при нулевом pull. |
| Явная попытка поставить на занятую клетку/X | Тихий отличимый reject без расхода хода. Release за пределами поля или pointercancel не являются ошибкой и молчат. |
| Перелёт хексов | Мягкие короткие tick/whoosh по фактическим `unitMoved` сегментам; звук не проигрывается пачкой при submit. Разрешена агрегация близких событий. |
| Набор и сбор десятки | Отличимый акцент сбора на presentation boundary и тихие ноты прибытия по flights[].end/увеличению отображённого счётчика. Не начислять очки через звук. |
| Появление новых стопок и смена очереди | Короткий pop на старте соответствующих segments; одинаковые одновременные события можно объединить. Initial board reveal молчит до разрешённого жеста. |
| Победа / поражение | Два разных коротких музыкальных завершения, один раз при появлении результата после timeline. На время завершения приглушить фон, затем восстановить; изменение props/resize/пауза поверх результата не повторяют фанфару. |

Звуковые семьи согласованы по громкости и тембру; фон не закрывает события. Непрерывный hum при удержании магнита не нужен. Защита от перегруза обязательна: предложенный предел 16 одновременно активных голосов суммарно, из них до 8 SFX; близкие tick можно объединять с интервалом не чаще 40 мс. Точные безопасные лимиты разрешено скорректировать по измерениям и прослушиванию. Не откладывать множество устаревших звуков в очередь. При низком FPS пропущенный интервал не должен порождать звуковой залп.

### 4.2. Настройки в паузе

- В существующий pause modal добавить две строки `Music` и `Sounds`: каждая с кнопкой `On`/`Off` и подписанным регулятором `0–100%`. Это явная интерпретация «кнопки по настройке»; сохранить Resume/Restart/close.
- Предложенные defaults: musicEnabled=true, sfxEnabled=true, musicVolume=0.35, sfxVolume=0.70. Значения — нормированные настройки канала, не обещание акустических dB. Volume=0 даёт тишину, не меняя сохранённый enabled; Off сохраняет выбранную громкость для последующего On.
- Отдельный versioned storage key, например `magnet-sort.audio.v1`; читать один раз при старте, писать при изменении настроек, не на кадре. Поля валидировать по типу и finite/range, неполные/повреждённые данные заменять defaults по полям; ошибки доступа к storage оставляют рабочие настройки в памяти.
- Переключения независимы и немедленны, с короткими gain ramps против щелчков. Restart/следующий уровень не сбрасывают предпочтения. Выключенный Sounds не должен воспроизводить собственный click; при включении разрешён один тихий confirmation. Volume slider не запускает музыку, пока игра на паузе.
- В обычной пользовательской паузе музыка и игровые SFX остановлены; UI click/confirmation разрешены через SFX-канал. При platform pause, hidden или blur — полная тишина, включая UI. Возобновление — по существующей логике пользователя, без самовольного старта при возвращении вкладки.
- Touch targets кнопок минимум 44 CSS px; нормальные focus/Tab/Enter/Space, доступные имена, состояние кнопки через aria-pressed либо role=switch/aria-checked. Проверить focus trap с range inputs, стрелки range не двигают игровую клетку. Состояние понятно без одного лишь цвета/иконки.
- Сохранить текущий визуальный стиль; на 320px portrait и 844×390 landscape настройки и основные кнопки доступны без горизонтальной прокрутки, при нехватке высоты modal прокручивается внутри.

### 4.3. Audio lifecycle и границы

Один аудиоконтроллер принадлежит runtime. Предлагаемый интерфейс: `unlockFromGesture`, `setSettings`, `setLifecycle`, `beginRun`, `beginTimeline`, `advanceTimeline`, `playUi`, `playResult`, `snapshot`, `dispose`; имена можно изменить при сохранении контракта. Независимые music/SFX gain buses, общий master; безопасные fade/stop/disconnect всех принадлежащих nodes.

- Не создавать/не запускать AudioContext до доверенного pointer/keyboard действия. `resume()` вызывать внутри такого обработчика, не после загрузки/await; rejected promise не приводит к unhandled rejection, следующая попытка возможна новым жестом. Загрузка и autoplay gate не блокируют играбельность; отключённые оба канала не требуют создания контекста.
- Музыкальные ноты планируются относительно audio clock. Допускается один owned lookahead timer, например 100 мс и горизонт до 250 мс; он работает только при нужном playback, очищается на mute/pause/hidden/dispose. Второй игровой RAF, frame-based высота тона и неограниченное планирование целого уровня запрещены.
- При паузе остановить уже запланированные игровые голоса и музыку, сохранить позицию партитуры. Resume продолжает с неё без второго loop; повторные lifecycle-вызовы идемпотентны. Reset/Next отменяют старый run/timeline/result и сохраняют единственную музыкальную дорожку, без её пересоздания на каждом ходе. Обещания unlock/restore не оживляют disposed или устаревший run.
- SFX привязываются к пересечению presentation boundary, а не вызовам `draw`. Дедупликация включает run/turn/segment/тип cue; рисование того же времени, resize, inspection и Preact rerender не озвучивают событие заново. Pause/resume не повторяют пройденные cues и не теряют ещё не наступившие. Timeline чистой модели не получает audio side effects.
- Reduced motion использует свои длительности той же timeline, не дублирует звуки и не меняет model events. Возможная агрегация сохраняет главные акценты. Отключение звука в середине хода немедленно останавливает канал; включение не проигрывает его прошлые события.
- Отсутствующий/недоступный AudioContext, отказ resume или audio-only ошибка дают рабочую беззвучную игру. Контролы остаются доступны; не открывать блокирующий экран ошибки поля ради аудио. HMR/dispose закрывает контекст, nodes, timers и listeners; повторный dispose безопасен.
- DEV snapshot содержит настройки, context state, число voices/timers/loops и небольшой bounded журнал cue IDs. Он помогает проверить поведение, но не заменяет анализ фактического сигнала/прослушивание. В production нет глобального gameDebug или растущих журналов.
