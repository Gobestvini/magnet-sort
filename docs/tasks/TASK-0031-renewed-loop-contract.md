## 4. Требуемое поведение

Согласовано пользователем 2026-10-12: начальные стопки при старте, пополнение после каждого сработавшего магнита; три видимых магнита без одинаковых цветов, использованный цвет может вернуться позже. Цель уровня N = 100*N реальных элементов, а не число стопок; превышение цели разрешено, HUD ограничивает полосу 100%. Магнит остаётся единственным действием игрока. Предложение автора: rulesVersion=4; сохранять соседний перенос и очистку по 6; без убывающего лимита, поражение при отсутствии легального размещения; ход без притянутых элементов считать сработавшим, если размещение принято. Сначала resolve/clear, проверить победу, затем пополнить поле и очередь; на победном ходу новые стопки не создавать. Это предлагаемые решения, их следует явно закрепить в спецификации.

Сохранять английский пользовательский интерфейс, pause/reset/hidden/dispose, доступный tap/drag/keyboard и reduced motion в применимой области.

## 5. План для исполнителя

1. Сопоставить новый запрос с model/runtime и перечислить заменяемые v3-контракты.
2. Задать pure state/events для RNG, spawn, queue, goal, movesUsed и stars; определить фазы presentation и момент начисления.
3. Зафиксировать стартовые численные настройки как изменяемые общие константы, не поля уровня. Предлагаемый baseline: 7 начальных стопок, после хода до 2 новых, по 3–6 хексов; выбор свободных клеток без замещения, оставить минимум одну легальную клетку, при недостатке места сократить спавн без бесконечного reroll. Выбор цветов/слоёв и взаимодействие с очередью описать явно.
4. Задать стартовые пороги звёзд: предложение 3 при movesUsed<=ceil(goal/12), 2 при <=ceil(goal/6), иначе 1 при победе, 0 при поражении. Проверить правдоподобие примерами, отметить отсутствие балансовой приёмки.
5. Описать примеры старт/принятый и отклонённый ход/нулевой pull/победа/нет места/reset; зарегистрировать зависимые задачи после проверки актуальности.
