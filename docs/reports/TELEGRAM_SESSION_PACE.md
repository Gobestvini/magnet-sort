# TASK-0069: сравнение темпа Telegram-сессии

2026-10-19. Статус **review**: техническая часть выполнена; сравнительная игра двух добровольцев и физический телефон недоступны на момент отчёта. Новые значения целей/спавна **не включены в production**.

## Рекомендация

Среди испытанных вариантов выбрать **B как кандидата для человеческой проверки**: цель `30+10*N`, действующий cadence1/2/3 сохранён. На L12 он дал40/50 greedy-побед против8/50 у A. В C пополнение на поздних уровнях ускорено до одного раза в2 хода: партии короче, но L12 получил4/50 побед. Ускорение притока одновременно усилило давление заполнения поля.

Это характеристика двух автоматических стратегий на seed0…49, не вероятность победы человека и не доказательство проходимости каждого seed. B ещё требует оценки: на L2 random выиграл50/50, ранние уровни могут стать слишком простыми. Не объявлять B готовым продуктовым балансом.

Текущий A оставлен без изменений. Следующий отдельный этап после playtest — решить, внедрять ли B целиком или испытывать гибрид с прежними ранними целями. Гибрид в этой работе **не проверялся**.

## Варианты и воспроизводимость

| Профиль | Цель | Пополнение L1–6 / L7–9 / L10–12 |
| --- | --- | --- |
| A | 50*N | 1 / 2 / 3 хода |
| B | 30+10*N | 1 / 2 / 3 хода |
| C | 30+10*N | 1 / 2 / 2 хода |

Общие параметры не менялись:5 стартовых стопок, высота6/10, clear10, блокеры, палитры/группы и radii1/2; размер партии меняется после5*N²/10*N² ходов. Общий kernel получил явную factory `createV4Rules` только с целями и интервалами. Default exports и production contentVersion остаются прежними.

Исходная ревизия измерения `b14de719ea200b8a6b889232014a6c813957774d`; при запуске были локальные изменения этой задачи. Это не выдаётся за чистый committed RC: [машинный итог](telegram-pace-summary.json) содержит SHA-256 каждого входа и `sourceDirty:true`. После измерения в ветку fast-forward добавлен документационный8e36e84 (закрытие звука); игровые входы не менялись. Воспроизводить по source-файлам итогового коммита и input hashes, не по одному старому SHA.

## Звёзды

Текущая формула:3 звезды при moves<=ceil(goal/12),2 при <=ceil(goal/6), иначе1. В B все победы greedy на L7–12 получили1 звезду. Изменение одной цели не даёт подходящих порогов эффективности.

Предложение для будущего playtest:3 звезды до p25 ходов победного greedy,2 до p60 с минимальным зазором1 ход; остальные победы1. Для короткого L1 квантиль может совпасть, поэтому второй порог расширен на1. Это эмпирические ориентиры из ограниченной выборки, не оценка shortest solution и не гарантия3 звёзд для любого seed.

## Играбельный DEV-preview и измерение

```powershell

```

Открыть [локальный экран сравнения](http://127.0.0.1:5188/tools/experiments/telegram-pace.html). Он использует текущую настоящую игру в iframe: общий bootstrap, renderer, input, audio, session и timeline. Parent передаёт factory только через DEV-gated hook; production hook/presets не содержит. Попытки обязательно transient, campaign storage не затрагивается. Это локальный инструмент, в публичный bundle не включён.

Браузерная проверка: A/B/C, L10 seed0, по3 реальных accepted действия, обычная анимация, последовательный запуск на одном Windows/Chromium153.0.8010.12, viewport1120×1080. [Девять замеров](telegram-pace-browser-timing.json): wall включает небольшой ввод/ожидание automation и превышает заданную timeline примерно на0.1–0.2с; ограничение ввода реально сохраняется до конца timeline. Это browser surrogate, не CPU/FPS benchmark и не физический телефон.

Preview позволяет выбрать P1/P2, профиль, уровень, seed, добавить наблюдения и добровольно скачать JSON. `activeSeconds` — видимое непоставленное на паузу время до появления результата, включая финальную collection при уже установленном model.terminal; версия измерения `through-result-2`. Это отдельно проверено реальной победой B/L1 в браузере: время продолжает расти в последней анимации. `idleSeconds` — часть видимого времени без accepted действия дольше15с. Idle — условная маркировка, не доказанное время без размышления. Данные не отправляются на сервер.

Для двух добровольцев: P1 играет A→B, P2 B→A, по одной раннейL1, среднейL6 и позднейL12 доске, seed0. Фиксировать поражения, ходы, активное/idle время, понимание момента спавна и желание повторить. Если seed0 проигран, оставить поражение в журнале. Не заменить его удачным seed. Результаты двух людей пока **не получены**.
